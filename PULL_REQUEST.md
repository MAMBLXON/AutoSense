## Часть I. Фичи (пункты 1–4 ТЗ)

- Экран-заглушка при пустой БД (`emptyState`): иконка, «Пока нет записей», кнопка «Добавить первую запись» (ведёт туда же, что и FAB).
- Все DAO-вызовы обёрнуты в `dbOp()` — try-catch + `Log.e` + Snackbar («Не удалось сохранить запись»), без крашей.
- Валидация (`ServiceUseCase`): название ≥2 симв.; интервалы — числа 0…9 999 999; дата строго ДД.ММ.ГГГГ, не в будущем; стоимость > 0. Ошибки — через `TextInputLayout.error`, кнопка «Сохранить» неактивна пока всё невалидно.

### 2. Свайп-действия
- Влево — удаление: красный фон + корзина, Snackbar «Запись удалена» с «Отменить» (4 сек, восстановление через RestoreItem).
- Вправо — редактирование: синий фон + карандаш, диалог с предзаполненными полями.
- Эффект Gmail: карточка сжимается до ~92% по смещению, alpha иконки растёт со свайпом. Заголовки категорий защищены от свайпа.

### 3. Поиск, фильтры, сортировка
- SearchView в тулбаре, live-фильтр по названию (debounce 300 мс), «Ничего не найдено» при пустом результате.
- Диалог фильтра по типам (Масло/Тормоза/Шины/Фильтры/Другое, мультивыбор OR), активные фильтры — чипы под тулбаром со снятием по «×».
- Сортировка: 4 варианта (дата ↑↓, пробег ↑↓), выбор сохраняется в SharedPreferences.

### 4. Редактирование записей
- Долгий тап → «Редактировать» (плюс свайп вправо) → диалог на `dialog_edit_item.xml`, полностью предзаполненный (название, интервалы, дата ТО, стоимость).

## Часть III. Баги 1–5 (корутины, гонки, миграции, 2038)
(`17a48ae`)
1. **Утечки корутин** — GlobalScope нет (проверено grep); все запуски через `viewModelScope`; подписки Activity переведены на `repeatOnLifecycle(STARTED)`; убраны два `runBlocking` в главном потоке (ANR-риск).
2. **Двойное нажатие «Сохранить»** — атомарный `AtomicBoolean.compareAndSet` guard вместо проверки флага; сброс в `finally` под `NonCancellable`; тот же паттерн в OnboardingViewModel.
3. **Поворот экрана при сохранении** — состояние в `MutableStateFlow` ViewModel переживает пересоздание Activity; подписка возобновляется на START; Save остаётся заблокированной на время записи.
4. **Room миграция** — проверено: `version = 7`, полная цепочка `Migration(1,2)…(6,7)` зарегистрирована; fallback не нужен.
5. **Переполнение Int для дат** — аудит всех `.toInt()`: ни одного на epoch-миллисекундах; AppPrefs работает через getLong/putLong; попутно исправлена ошибка типов в `AddViewModel.kt:142` (явный `val lastDateMillis: Long`).
